# 安全與信任內容檢查清單（2026-10-08）

每家交易所逐項回答：有／沒有／部分／未驗證。每項附證據網址（最終落地網址）、讀取方式、一句話說明頁上實際寫了什麼。「沒有」只在搜過站內（頁尾、說明中心、站內搜尋、Google `site:` 查詢）都找不到時才標；讀不到或被擋標「未驗證」，不寫「沒有」。

## A. 公司與責任歸屬
- A1 關於我們頁（公司介紹、成立年份、定位）
- A2 法律實體全名與註冊地址公開（頁面上看得到，不是只在條款深處）
- A3 管理團隊具名（姓名＋職稱）
- A4 牌照／登記專頁（逐一列出主體、監管機關、登記編號、可點到官方登記庫）
- A5 服務地區／受限國家清單
- A6 Media Kit／新聞室（品牌素材、新聞聯絡）

## B. 資產安全與透明
- B1 儲備金證明（PoR）常駐頁
- B2 PoR 由第三方會計師或審計方出具／驗證（寫出機構名）
- B3 PoR 用戶自驗（Merkle tree 或 zk proof）
- B4 PoR 歷史快照或報告列表
- B5 用戶保護基金（SAFU／Protection Fund），是否公開錢包地址
- B6 冷錢包比例或託管方式說明（有沒有寫數字）
- B7 第三方保險（寫出承保機構）
- B8 用戶資產隔離聲明（segregation，不挪用）

## C. 平台與帳戶安全
- C1 安全中心 Hub 頁（集中介紹平台安全、帳戶安全，並連到其他信任頁）
- C2 帳戶安全功能說明（2FA、提幣白名單、防釣魚碼、裝置管理、提幣鎖定）
- C3 第三方安全認證（ISO/IEC 27001、SOC 2 Type II、CCSS、PCI DSS 等，寫出名稱）
- C4 滲透測試或安全審計公開摘要
- C5 漏洞賞金計畫（平台、最高獎金）
- C6 `/.well-known/security.txt` 或負責任揭露政策頁（請直接 GET security.txt 檢查是不是真的文字檔）
- C7 官方渠道驗證工具（輸入網址／帳號查真偽）
- C8 反詐騙教育專區（集中頁或系列）
- C9 安全事件歷史或事後報告公開
- C10 系統狀態頁

## D. 合規政策與法律文件
- D1 用戶協議／服務條款
- D2 隱私政策
- D3 Cookie 政策
- D4 風險揭露（總則）
- D5 分產品風險揭露（合約、理財、質押等分開寫）
- D6 AML／KYC 政策公開頁
- D7 執法機關請求入口（Law Enforcement Request portal 或專用信箱）
- D8 Travel Rule 說明
- D9 上幣與下架標準公開
- D10 市場監控／公平交易政策（反操縱）

## E. 用戶服務與申訴
- E1 費率表
- E2 客服聯絡方式（24/7、即時客服、信箱）
- E3 正式客訴處理流程（受理時限、升級路徑、外部申訴機構）
- E4 透明度報告／年度報告

## F. Hub 結構（只對 C1 有的交易所填）
- Hub 網址、title、H1
- 首屏與各區塊順序（區塊標題原文）
- 連到哪些子頁（列出網址）
- 子頁的網址層級（是否都在 /security/ 或 /trust/ 底下）
- 是否在頁尾有入口、入口名稱
- Schema 類型（看原始 HTML 的 JSON-LD）
- 原始 HTML 是否含主要文字（curl 取回能否看到區塊正文）
